# Размещение Golos на одном сервере

Шаблоны подготовлены для Linux: один процесс Nest, nginx, PostgreSQL, Whisper и Ollama.
Пути, домен, Node binary и сертификаты заменить на реальные. Шаблоны не установлены
на сервер и не проверены командой nginx -t в этой среде.

## Окружение API

Скопировать golos-api/.env.example в .env на сервере, установить реальные значения:
NODE_ENV=production, HOST=127.0.0.1, PORT=3000, TRUST_PROXY=loopback,
FRONTEND_URL=https://ваш-домен, DATABASE_URL, случайный JWT_SECRET минимум 32 байта.
Для генерации секрета: openssl rand -hex 32. Не сохранять секрет в репозиторий.

WHISPER_URL и OLLAMA_URL должны указывать на сервисы, доступные с сервера API.
Адрес localhost не обращается к Mac разработчика. Модели и ffmpeg установить на
сервере моделей. Если сервисы в отдельных контейнерах, использовать их имена в сети.
Не открывать порты БД и моделей в интернет; снаружи доступны только HTTPS/HTTP nginx.

Встроенные лимиты: вход 5/мин с IP, регистрация 3/час с IP, ИИ 12/мин на пользователя,
одновременно до двух задач ИИ и одной на пользователя. Они хранятся в памяти одного
процесса. Не включать cluster/несколько реплик с общей моделью до переноса лимитов
и ограничения параллельности в общее хранилище. TRUST_PROXY задавать только для
действительно доверенных адресов прокси; nginx-шаблон заменяет X-Forwarded-For.

## Сборка и база

В golos-api выполнить npm ci, npm run build. Генерация Prisma входит в build.
Применить миграции: npx prisma migrate deploy --config prisma7.config.ts.
Для каталога слов: npx prisma db seed --config prisma7.config.ts.
Перед обновлениями сделать backup БД и проверить восстановление в отдельную БД.

В golos выполнить npm ci, npm run lint, npm run build. В .env.production задан
VITE_API_URL=/api. Переменная окружения сборки может его перекрыть. Не задавать
localhost в production. nginx раздаёт dist и проксирует /api с того же origin,
поэтому текущие SameSite=Strict cookies работают без межсайтовой авторизации.

## Запуск

Установить и проверить nginx-конфигурацию: nginx -t, затем перезагрузить nginx.
Установить unit из golos-api.service.example, подготовив пользователя golos и права
на каталог; проверить путь node. Запустить один API процесс под systemd. Модели
также должны иметь автозапуск и контроль состояния на выбранном сервере.
Для ручного запуска API предусмотрен npm run start:prod; он выставляет NODE_ENV.

GET /api/health — liveness. GET /api/health/ready — проверка БД, 503 при её отказе.
Настроить оповещение о 5xx/503, свободном месте БД и недоступности моделей.
Таймаут nginx 190 с рассчитан на отдельные запросы Whisper (180 с) и Ollama (120 с).
Браузер ограничивает запись 10 минутами и 10 МБ; API проверяет размер независимо.

## Проверки перед открытием доступа

В каждом проекте выполнить npm audit --omit=dev из среды с доступом к npm registry.
Не считать ошибки сети успешным аудитом. Проверить advisories до выпуска.

Для интеграционных тестов создать ОТДЕЛЬНУЮ PostgreSQL БД, применить миграции к ней:
DATABASE_URL=<test-url> npx prisma migrate deploy --config prisma7.config.ts
Затем в golos-api: TEST_DATABASE_URL=<test-url> npm run test:e2e.
Тесты создают свои аккаунты и слово, удаляя только созданные ими записи после прогона.
Они не запускают Whisper/Ollama; ответы и ошибки модели проверяются unit-тестами.

На staging вручную проверить: вход/выход, все разделы, сохранение и обновление
прогресса, реальные запись/Whisper/Ollama, запрет микрофона, Safari/mobile,
ограничения запросов и прямое открытие вложенного URL. Проверить нагрузку на
выбранных CPU/GPU. Публиковать только после успешного прогона.
